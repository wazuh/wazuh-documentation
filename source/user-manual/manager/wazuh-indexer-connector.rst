Wazuh indexer connector
=======================

The Wazuh indexer connector handles data exchange between the Wazuh manager and the Wazuh indexer. It replaces Filebeat, which shipped alerts and archived events from the Wazuh manager to the Wazuh indexer in Wazuh 4.x. The indexer connector is a shared library rather than a standalone daemon. It is linked to the Wazuh normalization engine, vulnerability detection service, and inventory synchronization service, which use it to exchange data with the Wazuh indexer. The ``wazuh-manager-clusterd`` daemon reads the same ``<indexer>`` block and reaches the Wazuh indexer through its own client.

The indexer connector transports data in the following flows:

-  **Outbound**: The Wazuh manager sends processed events, vulnerability data, and agent state documents to the Wazuh indexer for indexing, storage, search, and detection.
-  **Inbound**: The Wazuh manager retrieves content such as decoders, integrations, policies, key-value databases, and indicator of compromise (IOC) databases. It also retrieves runtime configuration for the Wazuh normalization engine. Events generated by the Wazuh normalization engine follow the :ref:`Wazuh Common Schema (WCS) <wazuh_common_schema>`. The normalization engine also synchronizes its state with the Wazuh indexer to ensure data consistency and reliability.

The indexer connector establishes TLS-secured connections to the Wazuh indexer and verifies the Wazuh indexer certificate against the Wazuh indexer CA. It authenticates with a username and password, which it reads from the Wazuh keystore rather than from the configuration file. For a Wazuh indexer that requires client certificates, the connector can also present a client certificate and private key that you configure. The :doc:`credential resolver <credentials>` stores the ``wazuh-manager`` username and the ``WAZUH_INDEXER_MANAGER_PASSWORD`` value, the password of the ``wazuh-manager`` user on the Wazuh indexer, in the keystore. When the Wazuh indexer runs on the same endpoint, the resolver also imports the Wazuh indexer CA from ``/etc/wazuh-indexer/export/``. Without these credentials, the Wazuh manager cannot start, and ``wazuh-manager-control`` prints ``Unresolved credentials. Exiting``.

To change these credentials, run the following commands as root:

-  ``/var/wazuh-manager/bin/wazuh-manager-keystore -f indexer -k username -v <USERNAME>``
-  ``/var/wazuh-manager/bin/wazuh-manager-keystore -f indexer -k password -vp <PASSWORD_FILE>``

where ``<USERNAME>`` is the Wazuh indexer user that the Wazuh manager authenticates as, ``wazuh-manager`` by default, and ``<PASSWORD_FILE>`` is a file whose first line is the password. The ``-f`` option selects the keystore family, ``-k`` selects the key, ``-v`` sets the value, and ``-vp`` reads the value from the first line of a file. Restrict the password file to root, for example with ``chmod 600``, and delete it after you run the command.

Then run ``/var/wazuh-manager/bin/wazuh-manager-control check`` and, when every check passes, restart the Wazuh manager with ``systemctl restart wazuh-manager``. The credential resolver doesn't replace a password that is already in the keystore with a value from the environment or ``/etc/wazuh-manager/local.env``, so the password you set persists across restarts. When the Wazuh indexer runs on the same endpoint and ``local.env`` doesn't set ``WAZUH_INDEXER_MANAGER_PASSWORD``, the resolver reads the password from ``/etc/wazuh-indexer/export/credentials.env`` instead. If that value differs from the stored one, for example after you reinstall the Wazuh indexer, every start replaces the stored password and prints ``replaced the indexer password in the keystore with the one from /etc/wazuh-indexer/export/credentials.env:<LINE>``. On such an endpoint, set the new password in ``local.env`` too, or the next start restores the value from the Wazuh indexer export.

.. warning::

   The indexer connector uses in-memory buffering. It discards buffered documents when the Wazuh manager stops or restarts. Ensure that the Wazuh indexer cluster can handle the expected data volume and event rate rather than relying on the Wazuh manager to absorb sustained indexing delays.

Configuration
-------------

Configure the Wazuh indexer connector in the ``<indexer>`` block of the ``/etc/wazuh-manager/wazuh-manager.conf`` file on the Wazuh manager. The default configuration is shown below:

.. code-block:: xml
   :emphasize-lines: 3-12

   <wazuh_config>
     ...
     <indexer>
       <hosts>
         <host>https://127.0.0.1:9200</host>
       </hosts>
       <ssl>
         <certificate_authorities>
           <ca>/etc/wazuh-manager/certs/indexer-ca.pem</ca>
         </certificate_authorities>
       </ssl>
     </indexer>
     ...
   </wazuh_config>

Where:

-  ``<indexer>`` specifies the configuration options for the Wazuh indexer connector.
-  ``<hosts>`` specifies a list of Wazuh indexer nodes to connect to. Use the ``<host>`` option to set up each node connection.
-  ``<host>`` specifies the URL of a Wazuh indexer node to connect to. The URL must start with ``http://`` or ``https://`` and include the Wazuh indexer port, 9200 by default. Without a port, the Wazuh manager uses the scheme's default port (``443`` for ``https://``, ``80`` for ``http://``) and can't reach the Wazuh indexer. For example, ``https://192.168.3.2:9200``. The installer sets it to the loopback address ``https://127.0.0.1:9200``.
-  ``<ssl>`` specifies the configuration options for the SSL parameters.
-  ``<certificate_authorities>`` specifies a path to one or more certificate authority (CA) certificates used to verify the Wazuh indexer TLS certificate. Use the ``<ca>`` option for setting up each CA certificate file path.
-  ``<ca>`` specifies the root CA certificate for HTTPS server verifications. The installer sets it to ``/etc/wazuh-manager/certs/indexer-ca.pem``, the CA of the Wazuh indexer. When the option is absent, the default is an empty list, which makes the connector use the system trust store. The allowed value is an absolute path to a PEM-encoded CA certificate in ``/etc/wazuh-manager/certs``.
-  ``<certificate>`` specifies the path to a client TLS certificate that the Wazuh manager presents to a Wazuh indexer that requires client certificates. The installer doesn't set it. The default is empty, which means no client certificate, and the connector authenticates with the ``wazuh-manager`` user and password only. Set ``<certificate>`` and ``<key>`` together. The client certificate must be issued by the Wazuh indexer CA and include the ``clientAuth`` extended key usage. The allowed value is an absolute path to a PEM-encoded certificate in ``/etc/wazuh-manager/certs``, for example ``/etc/wazuh-manager/certs/indexer-connector.pem``.
-  ``<key>`` specifies the path to the private key of the client certificate. The installer doesn't set it. The default is empty. Set it together with ``<certificate>``. The allowed value is an absolute path to a PEM-encoded private key in ``/etc/wazuh-manager/certs``, for example ``/etc/wazuh-manager/certs/indexer-connector-key.pem``.

You can learn more about the available configuration options in the :doc:`indexer </user-manual/reference/wazuh-manager-conf/indexer>` section of the reference guide.
