WCS field reference
===================

This page lists the fields of each WCS module. You can learn how the schema is organized in :doc:`How WCS works <how-wcs-works>`, how Wazuh fills the fields in :doc:`How Wazuh uses WCS fields <how-wazuh-uses-wcs-fields>`, and which fields to use first in :doc:`Key WCS fields <key-wcs-fields>`.

Table columns
-------------

Every table on this page describes one field per row. Each field set table lists its fields with the following columns:

-  ``Field``: The full name of the field as it appears in an event, including its field set prefix. For example, ``file.path`` or ``wazuh.agent.id``.
-  ``Type``: The data type the Wazuh indexer uses to store the field's value. For example, ``keyword`` for text such as ``user.name``, ``long`` for whole numbers such as ``file.size``, ``date`` for timestamps such as ``@timestamp``, and ``ip`` for IP addresses.
-  ``Level``: Where the field comes from. ``core`` and ``extended`` fields come from ECS. ``core`` fields are the most widely used, such as ``@timestamp`` and ``user.name``, and ``extended`` fields cover more specific cases. ``custom`` fields are added by WCS, such as ``agent.groups``.
-  ``Normalization``: ``array`` means the field is expected to hold a list of values, for example, ``process.args``. An empty cell means the schema sets no expectation. Any field can still hold a list of values of its type; for example, ``gen_ai.response.finish_reasons``.
-  ``Indexed``: Whether the Wazuh indexer indexes the field so you can search on it. Almost all fields are ``true``. Fields marked ``false``, such as ``event.original``, are stored in the event, but you can't search or filter on them.
-  ``Example``: A sample value for the field, as it would appear in an event. For example, ``/home/alice/example.png`` for ``file.path``.
-  ``Description``: A short explanation of what the field contains. For example, the description of ``file.size`` is "File size in bytes."

Event fields
------------

Event fields describe the normalized events that Wazuh stores in the ``wazuh-events-v5-<CATEGORY>`` data streams. The following tables show the `WCS field reference <|WCS_FIELDS_PAGE_URL|>`__, grouped by field set.

Each field set table starts with a one-sentence description of the field set. ECS field sets use their short description from `ECS 9.1.0 <https://github.com/elastic/ecs/tree/v9.1.0/schemas>`__. The field sets that WCS adds use the following descriptions:

-  ``wazuh``: Fields Wazuh adds to describe how it collected and processed the event.
-  ``check``: The results of Security Configuration Assessment (SCA) checks, including the condition, the result, the rationale, and the remediation.
-  ``policy``: The SCA policies that group the checks.
-  ``compliance``: The compliance requirements an event relates to.
-  ``mitre``: The MITRE ATT&CK tactics, techniques, and subtechniques an event relates to.

Findings index
--------------

The findings data streams store findings generated by detection rules. Wazuh creates one data stream for each event category, for example ``wazuh-findings-v5-security`` and ``wazuh-findings-v5-system-activity``. You can query all of them with the ``wazuh-findings-v5*`` index pattern.

Findings include all the fields of the main module, plus fields that describe the rule that matched and the case the finding belongs to:

-  ``wazuh.rule.*``: The rule that generated the finding, including its ID, title, level, and status, its MITRE ATT&CK mapping (``wazuh.rule.mitre.*``), its compliance requirements (``wazuh.rule.compliance.*``), and the Sigma rule it was imported from (``wazuh.rule.sigma_id``).
-  ``wazuh.case.*``: The case the finding is attached to, including its title, status, severity, priority, TLP classification, owner, and comments.
-  ``event.doc_id`` and ``event.index``: The ID and the backing index of the event that matched the rule.

The complete list of findings fields is in the `fields.csv <https://github.com/wazuh/wazuh-indexer-plugins/blob/|WCS_REF|/wcs/stateless/events/findings/docs/fields.csv>`__ and `wcs_flat.yml <https://github.com/wazuh/wazuh-indexer-plugins/blob/|WCS_REF|/wcs/stateless/events/findings/docs/wcs_flat.yml>`__ files of the ``stateless/events/findings`` module.

State indices
-------------

State indices store the latest known state of each monitored endpoint. Wazuh agent modules report the state, and the Wazuh manager keeps the indices in sync. Each index has its own module in the `stateful folder <https://github.com/wazuh/wazuh-indexer-plugins/tree/|WCS_REF|/wcs/stateful>`__, with a ``fields.csv`` file that lists its fields.

^^^^^^^^^^^^^^^
