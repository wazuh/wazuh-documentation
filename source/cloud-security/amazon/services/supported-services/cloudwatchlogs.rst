Amazon CloudWatch Logs
======================

`Amazon CloudWatch Logs <https://docs.aws.amazon.com/AmazonCloudWatch/latest/logs/WhatIsCloudWatchLogs.html>`__ is a service that allows users to centralize the logs from all their systems, applications, and AWS services in a single place. To understand how CloudWatch Logs works, it is important to learn about the following concepts:

-  **Log events:** CloudWatch saves the logs generated by the monitored application or resource as log events. A log event is a record with two properties: the timestamp when the event occurred and the raw log message.
-  **Log streams**: Log events are stored in log streams. A log stream represents a sequence of events coming from the application instance or resource being monitored. All log events in a log stream share the same source.
-  **Log groups**: Log streams are grouped using log groups. A log group defines a group of log streams that share retention, monitoring, and access control settings.

AWS configuration
-----------------

The following sections cover how to configure Amazon CloudWatch Logs to integrate with Wazuh.

Amazon CloudWatch configuration
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

The Wazuh module for AWS reads log events from existing CloudWatch Logs log groups through the AWS API. Before you configure Wazuh, get the name and Region of each log group you want to monitor. The module sends each log event to the Wazuh manager as it is. Wazuh decodes each log event with the integration that matches its format, so some events are indexed outside the AWS integration. For example, ``sshd`` syslog lines are decoded as system activity and can raise authentication findings. Wazuh doesn't index log events that no decoder classifies. To index your custom logs and raise findings for them, follow :doc:`Create a security analytics detection workflow </user-manual/data-analysis/detection-workflow>` to create decoders and rules.

Policy configuration
^^^^^^^^^^^^^^^^^^^^

.. include:: /_templates/cloud/amazon/read_only_policy_description.rst

   {

       "Statement": [
           {
               "Sid": "VisualEditor0",
               "Effect": "Allow",
               "Action": "logs:DescribeLogStreams",
               "Resource": "arn:aws:logs:<REGION>:<ACCOUNT_ID>:log-group:<LOG_GROUP_NAME>:*"
           },
           {
               "Sid": "VisualEditor1",
               "Effect": "Allow",
               "Action": "logs:GetLogEvents",
               "Resource": "arn:aws:logs:<REGION>:<ACCOUNT_ID>:log-group:<LOG_GROUP_NAME>:log-stream:*"
           }
       ]
   }

.. include:: /_templates/cloud/amazon/delete_policy_description.rst

.. code-block:: json
   :emphasize-lines: 8,17

   {
       "Version": "2012-10-17",
       "Statement": [
           {
               "Sid": "VisualEditor0",
               "Effect": "Allow",
               "Action": "logs:DescribeLogStreams",
               "Resource": "arn:aws:logs:<REGION>:<ACCOUNT_ID>:log-group:<LOG_GROUP_NAME>:*"
           },
           {
               "Sid": "VisualEditor1",
               "Effect": "Allow",
               "Action": [
                   "logs:GetLogEvents",
                   "logs:DeleteLogStream"
               ],
               "Resource": "arn:aws:logs:<REGION>:<ACCOUNT_ID>:log-group:<LOG_GROUP_NAME>:log-stream:*"
           }
       ]
   }

.. note::

   ``<REGION>``, ``<ACCOUNT_ID>``, and ``<LOG_GROUP_NAME>`` are placeholders. Replace them with the appropriate values.

For CloudWatch Logs, Wazuh deletes the log streams it has read instead of log files. It does so only if you set ``remove_log_streams`` to ``yes`` in the service configuration. This option is off by default and isn't in the sample configuration, so you need the second policy only if you turn it on.

After creating a policy, you can attach it directly to a user or to a group the user belongs to. In :ref:`attaching a policy to an IAM user group <attaching_policy_to_IAM_user_group>`, you see how to attach a policy to a group. More information on using other methods is available in the `AWS documentation <https://docs.aws.amazon.com/IAM/latest/UserGuide/id_users_change-permissions.html#users_change_permissions-add-console>`__.

Configure Wazuh to process Amazon CloudWatch logs
-------------------------------------------------

#. Make sure that the AWS integrations are enabled on the Wazuh dashboard, as described in :doc:`Enable AWS integration on the Wazuh dashboard </cloud-security/amazon/services/prerequisites/enabling-integration>`.
#. Add the following :doc:`Wazuh module for AWS </user-manual/reference/ossec-conf/wodle-s3>` configuration block in the ``/var/ossec/etc/ossec.conf`` file of the Wazuh agent to enable the integration with CloudWatch Logs. Replace the log group name and Region in the example with your own values. If the file already has a ``<wodle name="aws-s3">`` block, add only the ``<service>`` section to it:

   .. code-block:: xml
      :emphasize-lines: 7

      <wodle name="aws-s3">
        <disabled>no</disabled>
        <interval>5m</interval>
        <run_on_start>yes</run_on_start>
        <service type="cloudwatchlogs">
          <aws_profile>default</aws_profile>
          <aws_log_groups><LOG_GROUP_NAME></aws_log_groups>
          <regions>us-east-1</regions>
        </service>
      </wodle>

   You must specify at least one AWS log group to read logs from. You can add multiple regions by separating them with commas. If no region is specified, the Wazuh module for AWS looks for the log group in every available region.

   .. note::

      This example uses the ``aws_profile`` authentication parameter. Check the :doc:`Configure AWS credentials </cloud-security/amazon/services/prerequisites/credentials>` section to learn more about the different authentication options and how to use them.

#. Save the changes and restart the Wazuh agent service to apply the changes:

   .. code-block:: console

      # systemctl restart wazuh-agent

CloudWatch Logs use case
------------------------

Check the :doc:`Amazon ECR image scanning </cloud-security/amazon/services/supported-services/ecr-image-scanning>` section for an example of this integration. In that example, a Lambda function writes each Amazon ECR basic scan finding as a log event to the ``/aws/ecr/image-scan-findings/<REPOSITORY_NAME>`` log group. Wazuh reads these log events and raises the AWS ECR critical or high image vulnerability and AWS ECR image vulnerability findings.
